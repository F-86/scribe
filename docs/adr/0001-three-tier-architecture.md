# ADR-0001: 采用 L1/L2/L3 三层渐进式加载架构

> 状态:已接受 · 日期:2026-06-15 · 决策者:项目维护者

## 背景与问题

scribe 需要为多种文档类型(README、CLAUDE.md、CHANGELOG、API 文档……)提供各自的写作规范。这些规范加起来内容可观。问题是:agent 的上下文有限,如果每次文档任务都把全部规范载入,既浪费 token,也稀释了当前任务真正需要的内容。

## 决策

采用 Agent Skills 标准的 **L1/L2/L3 三层渐进式加载**:
- L1(frontmatter)始终在上下文,只负责"要不要触发"
- L2(SKILL.md 正文)命中后加载,负责流程与路由
- L3(references/*.md)按文档类型**按需**加载,每类一份

## 理由

- **上下文经济**:只加载当前文档类型的规范,与文档种类数量解耦——再多类型也不增加单次任务的基础开销
- **符合开放标准**:三层是 Agent Skills 规范的既定模式,跨工具通用
- **职责隔离**:L3 之间互不依赖,新增/修改一类不影响其他

## 备选方案

- **单文件全量**:所有规范写进 SKILL.md。简单,但每次加载全部,上下文浪费随类型增长线性恶化,否决。
- **两层(L1+L2,无 L3)**:规范全塞 L2 正文。同样面临 L2 过重问题,且无法按需取用,否决。

## 后果

- ✅ 单次任务只载入相关规范,新增文档类型不影响既有任务的上下文开销
- ✅ 规范模块化,易独立维护
- ⚠️ 新增一类文档需同步多处路由(见 [ADR-0003](0003-doc-map-as-single-source.md) 之后仍存在),靠 CONTRIBUTING 清单约束
