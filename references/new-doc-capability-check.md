# 新建文档：封装项目已有能力的检查流程

> 仅在用户要求新建的文档要封装/描述项目里已有的功能时加载（如写 SKILL.md / API 文档 / CLAUDE.md，需要写清"调用哪个脚本/函数/接口"）。

## 核心原则

用户常常不会主动说明项目里是否已有相关实现。**先问一句，让用户决定，不要擅自扫描或擅自臆造**。

## 询问话术

> 这个功能（如统计 MySQL/Redis）项目里已经有实现代码了吗？如果有，告诉我在哪几个文件（或让我去看），我据此写出可执行的调用流程；如果没有，我直接为你写出实现脚本 + 配套文档。

## 分支处理

| 用户回答 | 操作 |
|---------|------|
| **"有"** | 让其提供路径或按功能关键词**定向**定位那几个文件，读懂真实调用方式后再写。**不要在没看过实现的情况下凭空写"调用相应脚本"这类无法执行的占位流程**（违反「可执行 > 抽象」与「不虚构」）。|
| **"没有"** | 不扫描项目，直接编写实现脚本与配套文档。|
| **不确定** | 按"没有"处理，或按功能关键词快速定向查找确认，不全库遍历。|
