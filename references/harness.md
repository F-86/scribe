# Harness 视角

本 Skill 的重点不是"提示词"，而是一个小型 harness。它要回答六个问题：

| Harness 部分 | 本 Skill 解决的问题 | 设计手段 |
|---|---|---|
| 上下文管理 | 模型到底看到了什么 | 渐进加载 references：Intake 只看轻量识别表，Plan 再加载对应 L3 模板，Review 才读质检清单 |
| 工具系统 | 能处理什么输入/输出 | 用户粘贴 / 文件路径读取；输出为项目文档文件 |
| 执行编排 | 下一步该做什么 | 分 Phase、检查点、先写计划再出初稿再审阅修复的流程 |
| 状态与记忆 | 决策如何跨步骤保持 | `.scribe/` 工作区：`plan.md`（写作计划）、`review.md`（评审记录） |
| 评估与观测 | 怎么知道文档写得好不好 | 内联自查清单（简单格式/完整性问题） + 可选的 SubAgent 评审（复杂文档） |
| 约束与恢复 | 跑偏后怎么修 | Checkpoint 用户确认制、不覆盖已存在文件、修复不走整篇重写 |

## 工作区文件（.scribe/）

Agent **不应依赖聊天上下文记住关键决策**。跨阶段决策落盘到下列文件：

```text
.scribe/
  plan.md              # 写作计划：文档类型、目标受众、大纲、基调提示词
  draft.md             # 当前草稿（初稿或最新版，始终只保留一份）
  review.md            # 评审记录：内联自查结果 / SubAgent 评审结论
```

长会话中如果不确定某个已确认的决策，**回读这些文件**，不要凭记忆重新发明。

## 一句话定位

> Scribe 把零散的文档需求变成结构化的写作流程：先想清楚写什么再动笔，每一步都有人检查——不是替你写文档，是帮你把文档写对。
