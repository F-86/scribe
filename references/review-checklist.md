# Scribe 质检清单

## Plan 自查段（主 Agent 内联，不开 SubAgent）

写完后主 Agent 就地逐项检查：

1. **目标受众是否明确？** 写给开发者、AI agent、项目新成员、还是其他角色？不同受众导致不同的结构和语气。
2. **信息范围是否界定？** 哪些信息必须保留、哪些可删——这些和用户确认过吗？
3. **Outline 是否覆盖了用户指定的所有重点？** 不要遗漏用户提过的关键内容。
4. **章节之间有没有明显缺失？** 比如 README 少了安装步骤、SKILL.md 少了 When to Use。
5. **这份计划如果给用户看，用户能不能看懂并做决策？** 避免内部术语和模糊表述。

按结论修复 plan.md，然后进入 Checkpoint 1。

---

## Draft 自查段（主 Agent 内联，不开 SubAgent）

初稿写完后，主 Agent 就地逐项检查：

1. **信息完整性**：计划里确认要包含的内容都写进去了吗？有遗漏吗？
2. **不虚构信息**：有没有任何内容是推断的、没确认的？有则标 `<!-- TODO -->`。
3. **格式正确性**：Markdown 渲染有没有明显问题（表格对齐、代码块标记、链接语法）？
4. **语言一致性**：全文风格是否统一？中英文混合是否合理？
5. **可执行 > 抽象**：每条建议是否可操作？"运行 `npm test`"好于"进行测试"。

按结论修复 draft.md，然后进入 Phase 4 Review。

## Final Review 段（复杂文档用 SubAgent 评审）

### 评审 prompt 模板

```
你是一名文档审阅专家。请根据以下清单评审提供的文档草案。

找出全部 issues，按优先级分组：
🔴 必须修 — 影响正确性或可用性的问题
🟡 建议改 — 可优化但不是阻塞项
🟢 可选优化 — 锦上添花

每条 issue 给出：具体位置 + 问题描述 + 修改建议
```

### 通用检查项

#### 结构完整性
- [ ] 文档有明确的标题和介绍段
- [ ] 一级标题和二级标题层次合理，不跳跃
- [ ] 所有章节有实质内容（不是空标题）
- [ ] 没有遗漏关键章节（安装/使用/配置/贡献等，视类型而定）

#### 内容正确性
- [ ] 所有引用、链接、命令、配置是正确的（标注 TODO 的除外）
- [ ] 术语使用一致（不混用同义词指同一个概念）
- [ ] 没有过时或已经废弃的信息
- [ ] 示例代码可以实际运行（标注 TODO 的除外）

#### 语言和可读性
- [ ] 每个段落只表达一个核心意思
- [ ] 语言简洁，没有冗余修饰
- [ ] 中英文混排符合规范（中文和英文之间加空格）
- [ ] 语气一致（正式/非正式取决于目标受众）

#### 格式
- [ ] 代码块有指定语言（```python 而不是 ```）
- [ ] 列表风格一致（全用 - 或全用 *，不混用）
- [ ] 表格有表头和对齐标记
- [ ] 内链和外链语法正确
