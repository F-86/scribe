# FAQ / 故障排查编写指南

## 定位

这类文档帮使用者**自助解决问题**,减少重复提问。它包含两种形态,写法不同,动笔前先分清(边界见 [`doc-map.md`](doc-map.md)):

| 形态 | 回答 | 组织方式 |
|------|------|---------|
| **FAQ(常见问题)** | "这个支持 X 吗?""为什么是这样?" | 问答对 |
| **故障排查(Troubleshooting)** | "报这个错怎么办?""为什么不工作?" | 症状 → 原因 → 解决 |

二者都可独立成文,小项目也可作为 README 的一节。

## 一、FAQ

### 结构模板

```markdown
# 常见问题

## 安装与配置

### 支持 Windows 吗?
支持 Windows 10+。注意路径需用 `\\` 或正斜杠。

### 可以离线使用吗?
可以。首次安装需联网下载依赖,之后纯本地运行。

## 使用

### 免费版和付费版有什么区别?
免费版每天 100 次调用,付费版无限制。详见[定价](https://...)。
```

### 编写原则

**DO ✅**
- 用**用户真实会问的话**做标题,不用术语包装("怎么导出?"而非"导出功能说明")
- 一问一答,答案直接给结论,需要展开再补一两句
- 按主题分组(安装/使用/计费),问题多时加锚点目录
- 答案里能链接到详细文档就链接,不重复抄

**DON'T ❌**
- 不要编造"常见"问题——FAQ 应来自真实提问(issue、支持记录、社区)
- 不要把 FAQ 写成完整教程——它是补充,不是主文档
- 不要让答案过期——功能变了要同步

## 二、故障排查

### 结构模板

每个条目固定三段:**症状 → 原因 → 解决**。

```markdown
# 故障排查

## 安装报错 `EACCES: permission denied`

**症状**:运行 `npm install -g xxx` 时报权限错误。

**原因**:全局目录需要管理员权限,或 npm 默认目录配置不当。

**解决**:
1. 优先用 nvm 管理 Node,避免 sudo:`nvm use 18`
2. 或修改 npm 全局目录到用户空间:
   ```bash
   npm config set prefix ~/.npm-global
   ```
3. 仍失败?见[下方"如何收集诊断信息"](#如何收集诊断信息)。

## 启动后页面空白

**症状**:服务启动无报错,但浏览器打开是白屏。
**原因**:多为前端构建产物缺失,或 API 地址配置错误。
**解决**:
1. 确认已执行 `npm run build`
2. 检查 `.env` 里 `API_URL` 是否指向正确后端
3. 打开浏览器控制台看具体报错
```

### 编写原则

**DO ✅**
- **症状用用户看到的现象描述**(报错原文、白屏、卡住),用户靠现象来匹配,不靠原因
- 把报错信息原文写进标题或症状里——用户会直接搜报错文本
- 解决步骤可执行、有顺序,从最可能的原因排起
- 提供"兜底":列一个"如何收集日志/诊断信息"的通用条目,解决不了时知道下一步找谁

**DON'T ❌**
- 不要只写原因不写解决——用户要的是"怎么办"
- 不要假设用户懂内部原理——解决步骤要能照着做
- 不要把罕见问题堆在前面——按发生频率排序

## 章节取舍

| 内容 | 何时需要 | 何时可省 |
|------|---------|---------|
| FAQ | 有重复的"是什么/支持吗"类提问 | 无 |
| 故障排查 | 有重复的报错/不工作类提问 | 极简工具 |
| 诊断信息收集 | 排障复杂、需要用户提供日志 | 简单项目 |
| "仍未解决"求助入口 | 始终建议 | 无 |

## 通用规则

- **来自真实问题**:FAQ 和排障条目应源自真实 issue/提问,不虚构。没有素材时问用户"用户最常遇到什么问题"
- **优先从已有素材提取**:有 issue 列表、支持记录、报错日志时从中提炼高频问题
- **单一信息源**:答案能指向已有文档就链接,不把教程内容抄进来
